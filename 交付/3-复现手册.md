# 复现手册

目标：**在另一台 macOS 上，从零复现这套接力台，并自己跑出同样的验收结果。**

## 0. 前置条件

| 项 | 要求 | 怎么确认 |
| --- | --- | --- |
| Node.js | ≥ 20（实测 v24.18.0） | `node -v` |
| 第三方依赖 | **零**（不使用 npm 包） | 不需要 `npm install` |
| DeepSeek Harness | 已安装 App | `dsh --profile headless --json "只回复 OK"` |
| Codex | 已登录 | `codex login status` |
| MiniMax | `mmx` 已登录 | `mmx auth status` |
| Kimi | Kimi 桌面版已登录（提供 daimon 共享配置） | 见 §3 |
| Xcode 命令行工具 | 仅编译热键守护进程需要 | `swiftc --version` |

## 1. 启动中台

```bash
cd relay-deck
node server.mjs            # 默认 http://127.0.0.1:8787
```

浏览器打开 <http://127.0.0.1:8787/>。

## 2. 跑一遍验收（不需要板子）

```bash
node --test                         # 期望 61 项全绿
node bin/relay.mjs agents           # 期望列出 4 个 Agent 及其命令路径

# 跨 Agent 接力（会真实调用模型）
node scripts/e2e-http.mjs dsh codex
node scripts/e2e-http.mjs dsh minimax
node scripts/e2e-http.mjs dsh kimi
# 期望：每组 11/11 项通过，结果写入 evidence/

# 边界验证（含两次真实模型调用）
node scripts/e2e-boundary.mjs       # 期望 10/10

# 硬件链路（不需要板子）
swiftc -O tools/hotkeyd.swift -o tools/hotkeyd
./tools/hotkeyd --selftest          # 期望 4 个动作全部 ✓
node bin/simulate.mjs demo
```

## 3. 各 Agent 的接入前提（踩过的坑都在这里）

### DeepSeek Harness

`dsh` 不在 PATH 上，适配器按候选路径探测 App 包内的可执行文件。要换位置就设 `RELAYDECK_DSH_BIN`。

### Codex

```bash
codex login status     # 必须是已登录
```

适配器固定带 `--skip-git-repo-check`（不在 git 仓库里也能跑），`resume` 走另一套参数。

### MiniMax

```bash
mmx auth status        # oauth 登录态
mmx quota show         # 能返回额度说明鉴权链路是通的
```

**注意**：`--messages-file -` 只认**裸数组** `[{...}]`；写成 `{"messages":[...]}` 会报 `s is not iterable`。

### Kimi

```bash
# 桌面版与 CLI 共用的 daimon 配置（必须显式指过去，否则报 adapter config missing）
ls "$HOME/Library/Application Support/kimi-desktop/daimon-share/daimon/config.json"
# 自检
DAIMON_CONFIG_PATH="$HOME/Library/Application Support/kimi-desktop/daimon-share/daimon/config.json" \
"/Applications/Kimi.app/Contents/Resources/resources/daimon-bundle/bin/kimi-daimon" \
  --node "$(command -v node)" --prompt "只回复：收到"
```

**注意**：正文只能走 `--prompt`（stdin 是它的控制命令通道）；日志和回答都在 stdout；它持有 `runner.lock`，所以同一时刻只能跑一轮——中台的按 Agent 串行队列就是为它加的。

### ZCode（当前未接入）

```bash
node "/Applications/ZCode.app/Contents/Resources/glm/zcode.cjs" login   # 先登录
```

登录成功后再照 MiniMax 的模式写适配器（它有 `--json` 与 `--resume <sess_...>`）。当前报 `Model creation failed`，完整排查记录见 [Agent 接入手册](../docs/agent-onboarding.md)。

## 4. 硬件接入（板子回来后）

> 固件里**已经存在**「把 Agent 状态显示到 5 颗灯」的协议（Agent Status v1，report `0x12`），不需要自己造一套。完整的字节布局、状态映射与实板验收步骤见 [阶段2b 清单](../docs/hardware-stage2b.md)。

### 4a. 零固件改动的第一步（HID 组合键）

1. 启动全局热键守护进程：

```bash
swiftc -O tools/hotkeyd.swift -o tools/hotkeyd
./tools/hotkeyd
# 若提示无法创建事件监听：系统设置 → 隐私与安全性 → 辅助功能 → 勾选你的终端
```

2. 在 EasyInput App 里把按键配成同样的组合键（与 `src/hardware/keymap.mjs` 的 `DEFAULT_HID_KEYMAP` 一致）：

| 部件 | 组合键 | 动作 |
| --- | --- | --- |
| S1–S5 | ⌥⌘1 – ⌥⌘5 | 接力给第 1–5 个 Agent |
| S6 | ⌥⌘Esc | 清空焦点 |
| S7 | ⌥⌘C | 复制焦点句 |
| S8 | ⌥⌘B | 拉群并汇总 |
| 旋钮逆/顺时针 | ⌥⌘← / ⌥⌘→ | 焦点上/下一句 |
| 旋钮按下 | 需要时映射为 ⌥⌘0 | 切换查看的 Agent |

3. 验证：按住 ⌥⌘C，看剪贴板是否变成当前焦点句；按 ⌥⌘1，看是否真的发起一轮接力。

### 4b. 结构化命令 + LED 回传（需要改固件）

板子侧只需要打**一个** HTTP 接口：

```bash
curl -X POST localhost:8787/api/hardware -H 'Content-Type: application/json' \
  -d '{"source":"key","id":"S1","gesture":"press"}'
```

返回体里带 `led.pixels` 与 `led.frame`（15 字节 GRB），直接写到 5 颗 WS2812 即可。也可以只轮询：

```bash
curl -s localhost:8787/api/hardware/led
```

固件改动必须遵守 `easy-input-maker/AGENTS.md`：不动 GPIO/BOOT/分区/GPIO8 共享电源时序，不提交真实凭据与设备标识，四类证据分开报告。

## 5. 常见故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `无法启动 <path>：spawn ... ENOENT` | 适配器的二进制路径不对；检查环境变量或注册的候选路径 |
| `超时（Nms）后已终止` | 模型太慢或任务太长；调 `RELAYDECK_TIMEOUT`（毫秒） |
| 一次正确回答被判成失败 | 检查是不是把条目级警告当成了致命错误（Codex 的 chronicle 警告） |
| 接力后下游答非所问 | Agent 没有续跑能力且没拿到历史；确认 `capabilities.resume` 与 `buildHistoryPrompt` 生效 |
| Kimi 报 adapter config missing | 没设 `DAIMON_CONFIG_PATH` |
| Kimi 第二轮失败 | 上一轮还没退出、`runner.lock` 被占用；串行队列应已挡住，检查是否绕过中台直接调用 |
| 网页端按键无效 | 中台页面不在前台；用全局热键守护进程，或走 4b 的结构化命令 |
| 端口的 404 满天飞（ZCode/Kimi） | 那是私有 IPC 桥，不是 REST API，别爆破 |

## 6. 环境变量一览

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `RELAYDECK_PORT` | 中台端口 | `8787` |
| `RELAYDECK_TIMEOUT` | 单轮超时（毫秒） | `180000` |
| `RELAYDECK_CHAIR` | 圆桌主持人 | `dsh` |
| `RELAYDECK_DATA` | 数据目录 | `./data` |
| `RELAYDECK_DSH_BIN` / `_CODEX_BIN` / `_MMX_BIN` / `_KIMI_BIN` | 覆盖各 CLI 路径（**显式设置即生效，不存在会立刻报错**） | 自动探测 |
| `RELAYDECK_KIMI_CONFIG` | daimon 共享配置路径 | 桌面版默认位置 |
| `RELAYDECK_MMX_MODEL` | MiniMax 模型 | CLI 默认 |
| `RELAYDECK_URL` | 验收脚本指向的中台地址 | `http://127.0.0.1:8787` |
| `RELAYDECK_HARDWARE_URL` | 热键守护进程指向的接口 | `…/api/hardware` |
