## 二、跨 Agent 接力验收（三组，各 11/11）

```bash
node scripts/e2e-http.mjs dsh codex      # → evidence/http-e2e-2026-10-07T14-01-56-213Z.json
node scripts/e2e-http.mjs dsh minimax    # → evidence/http-e2e-2026-10-07T13-55-20-177Z.json
node scripts/e2e-http.mjs dsh kimi       # → evidence/http-e2e-2026-10-07T13-57-24-542Z.json
```

每组 11 项检查，关键三项：

1. 上游答出"已记住 42"；
2. 下游（自己会话里没有 42）**靠接力上下文答出 42**；
3. 对没有续跑能力的 Agent，**不给接力上下文**再问一轮，靠中台补的历史仍然答对（有续跑能力的 Agent 此项标记为"跳过"）。

同时验证：会话隔离（两个会话的续跑线不同）、消息不跨会话、搜索命中、接力链可回溯、用量有记录。

## 五、续跑线失效自愈（7/7）

```bash
node scripts/e2e-session-recovery.mjs    # → evidence/session-recovery-2026-10-07T14-05-56-170Z.json
```

脚本**自己制造故障**：正常跑一轮拿到真实续跑线 → 把数据文件里这条线改成一个不存在的 session（模拟会话过期/被删/换机器）→ 调 `POST /api/admin/reload` 让改动生效 → 再发一轮。

| 检查 | 结果 |
| --- | --- |
| 第 1 轮正常建立续跑线 | ✅ |
| 故障已注入（内存里确实是坏 session） | ✅ `session-nonexistent-…` |
| **坏 session 下仍然成功产出** | ✅ 自愈生效 |
| 如实上报 `contextReset` | ✅ 用户能看到"上下文已重置" |
| 重试只有一次 | ✅ `attempts=2` |
| 坏线被替换成新线 | ✅ |
| 后续轮次恢复正常（不再重置） | ✅ `attempts=1` |

修复前的行为（实测记录）：每一轮都返回 `session "…" does not exist; omit --session-id to start a new Session`，**永久失败且无法自愈**。

## 六、重启恢复

```bash
curl -s localhost:8787/api/state > /tmp/before.json
# 杀掉中台再启动
curl -s localhost:8787/api/state > /tmp/after.json
diff /tmp/before.json /tmp/after.json    # 无差异
```

实测：重启前后**完全一致**（8 个会话、当前会话与消息数不变），`data/store.jsonl` 中保留 8 条续跑线。

## 十、没有证据的部分（如实列出）

- **实板验证**：没有。板子在做另一门课，尚未烧录实测；因此"真机按键 → 接力""实板点亮 LED"都没有实测记录，只有模拟器与自检。
- **ZCode**：没有成功记录，只有失败排查过程（见 [Agent 接入手册](../docs/agent-onboarding.md)）。
- **弱网（高丢包/高延迟）**：没有真实构造。目前只覆盖了"子进程超时被终止"与"二进制不存在"这两种失败路径。
- **多用户与鉴权**：没有，中台只监听 127.0.0.1。
